# Architecture Review & Feature Roadmap: SimMatrix**Project Context:** Architectural feedback and optimization strategies for the "SimMatrix" (formerly RaceRipp_Overlay) Assetto Corsa Competizione (ACC) telemetry app. ---## 1. Project Renaming & RefactoringThe project is officially transitioning to the name **SimMatrix**. Please update the workspace references:* Update `package.json` and `src-tauri/tauri.conf.json` with the new app name.* Update `README.md` headers and ASCII architecture diagrams to reflect **SimMatrix**.* Update name on new releases and Everything else that needs to change## 2. Core Architectural Principles* **Fallback Design (Crucial):** All overlays must function fully as standard live overlays using ACC Shared Memory data if no MoTeC file is uploaded. The MoTeC comparison engine must act as an opt-in, non-blocking layer.* **Maintain Decoupled State:** Keep the core layout intact. The Python sidecar handles memory mapping and heavy interpolations, broadcasting lightweight JSON objects via WebSockets to the Tauri/HTML frontends.## 3. Telemetry & MoTeC Optimization Roadmap### A. High-Precision Distance Matching (Replacing Velocity Integration)Currently, integrating velocity over time to calculate distance introduces a slight drift (~15ms at Spa). To achieve perfect sync between live telemetry and static MoTeC traces:* **Leverage ACC Physics Engine:** Read `Graphics.normalizedCarPosition` (0.0 to 1.0) directly from the ACC Shared Memory API.* **Convert to Meters:** Multiply this percentage by `Static.trackLength` to get the vehicle's exact position on the track in meters.* **Linear Interpolation (Lerp):** In the Python engine, map this live meter variable against the MoTeC `.ld` distance-time array to interpolate the delta and reference channels instantly.### B. Advanced Overlay Enhancement (Ghost Inputs)* **Piping Reference Data:** Extend the WebSocket JSON frame payload to include reference lap telemetry data at the current track meter (`refThrottle`, `refBrake`, `refSpeed`, `refSteer`).* **UI Update (`inputs-trace`):** Modify the HTML/Canvas components in the overlay modules to render semi-transparent "ghost" bars or outline paths right behind the active user inputs. This allows drivers to visualize driving line and input differences dynamically in real-time. Do this in a way that aligns with professional and described ways/styles.
